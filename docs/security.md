# Authorization and execution

The owner supplies standard Kubernetes RBAC for investigator and executor workload access. `policy.authorization=RBAC` imposes no resource/path/value catalog. Namespace enrollment configures where the operator watches; it is not a replacement for Kubernetes authorization. The executor performs SelfSubjectAccessReview checks before dry-run and again before the conditional write. The actual API request remains subject to current RBAC and cluster admission.

The chart provides protocol permissions separately from workload permissions. Its default workload grant is empty (`workloadRBAC.preset: none`); the `observe` and `repair` presets grant namespaced Roles in enrolled namespaces only, never Secrets writes or RBAC. The only cluster-scoped permission is `list` on StorageClasses for the investigator, rendered only when `policy.repairs.storage.replaceUnboundClaims` is enabled. Fine-grained field restrictions belong in owner admission policies.

Repair actions preserve resource identity, UID, resourceVersion and status. Plans bind task UID, generation, monitoring cycle, target UID/configuration digest, configuration digest, exact actions and verification. Resource status churn does not invalidate a plan. The Deployment controller's revision annotation is excluded from the configuration digest; other annotations remain bound. Cluster-scoped execution and arbitrary shell are not implemented. Own CRDs and reserved `agent-` coordination Leases are protected protocol infrastructure.

The investigator can create Pending requests for HumanApproved tasks, and Approve requests only for owner-selected Automatic tasks. Operator identities cannot change task intent or mode, or approve HumanApproved requests. Human users patch only a Pending request's decision to Approve or Reject. Bindings are immutable and a decided request cannot be changed. Requests expire within 30 minutes; replacement requests retain the exact plan binding. Changing generation, cycle, target identity or relevant configuration invalidates old authorization.

Admission checks authenticated status ownership, immutable plan/approval bindings, current task cycle, consumed approval, live target claim, pending journal and the exact resulting workload object, including mutating-webhook effects. Executor status writes cannot restore an old plan or investigation cycle. The investigator cannot write workloads through this admission path even if owner RBAC permits it. Unrelated human workload writes are outside the operator ServiceAccount selector. Deletions of operator records by other identities bypass the webhook (the validator always allowed them), so deleting a namespace or a broken release never deadlocks on an unreachable admission Service; operator-identity deletions are still validated. Resources labelled `app.kubernetes.io/part-of: periscope` (the operator's own workloads) are rejected as repair targets by the shared action authorizer, which the investigator, executor and admission all apply.

Execution records durable intent before a write and uses target claims, conditional UID/resourceVersion and idempotency markers. Restarting after an ambiguous write reconciles the observed object and journal. API acceptance and application recovery are separate outcomes. Monitoring yields to an active execution journal, retains learned verification after completion and invalidates pending authorization when external changes resolve an incident.

Evidence includes bounded resource context, Events, Pod logs and API schema. Secret data is never projected. Recognized credential fields, URL userinfo, authorization/cookie headers, literal values of credential-named environment variables and credential strings are redacted; annotations are excluded. Names of referenced objects (secretName, secretKeyRef, configMapKeyRef, envFrom, imagePullSecrets) are retained so broken references can be diagnosed, and executable actions may contain them. This cannot recognize every possible secret encoding. Provider credentials are mounted from an existing Secret in the investigator only. When `policy.repairs.secrets` is enabled, a plan may create a missing Secret, but it names keys only (`secretSources`); the executor fills values at write time from a cryptographic random source or from owner-listed source Secrets. With secret creation enabled the executor and admission may `get` Secrets in enrolled namespaces (to copy allowed sources and confirm their own writes); the investigator never can. The investigator, the model, plans, journals and evidence never hold a value: digests in plan status cover key names only, and admission checks that the written keys match the plan. Existing Secrets are never changed. Experimental application-error detection reads recent container logs; matched sample lines are redacted and bounded like other evidence. Resource text, logs and retrieved documents are evidence, never instructions authorizing access or execution.

`LegacyCatalog` remains an explicit compatibility mode for previous fixtures and regression tests. The default and deployed mode is RBAC; changing authorization configuration changes the plan digest and requires fresh authorization.


Scoped healing extends exact authorization to every related resource and original goal check. Multi-resource journal baselines chain only actions on the same resource. Claim acquisition is deterministic and releases partially acquired claims on contention. Explicit delete/create binds the old UID and a later absence established by the confirmed deletion journal; it grants no implicit recreation fallback.

Optional Prometheus arbitrary queries are accepted only against an owner-established SingleNamespace/OwnerTenant data boundary matching the task namespace set exactly. Resource-filtered tasks cannot use broader namespace metrics. Adding a namespace label to arbitrary PromQL is not an access-control boundary inside the operator; the endpoint must enforce it, for example prom-label-proxy with a fixed `--label-value` in front of a cluster-wide Prometheus (verified live: a query for another namespace is rewritten to the enforced one). Limits cover query ranges, response size, series and points.

Enabled observation credentials are read-only mounts in investigator, executor and admission so all three can independently observe the original goal. These credentials must have a scoped read-only evidence boundary and are separate from the investigator-only provider key. Native network probes have a distinct bearer credential and owner-declared destinations. The owner installs the sidecar; the operator never injects it or runs model-authored shell/exec. Probe endpoints and returned vantage are pinned to a monitored Pod UID. Replaced Pods need owner endpoint reconfiguration. HTTPS is the default; plain HTTP needs an explicit owner choice and does not protect bearer traffic on the network.

Rolling inference budgets reserve calls durably before provider/tool use, including errors. Health observation continues during inference exhaustion. Stored incident checks cannot be replaced by model-selected easier checks; stable success requires concrete results from the original contract. Typed checks define the evidence this version can verify. They do not establish universal application correctness.


Task record namespaces share one configured coordination namespace. Claims use a logical namespace/API-group/kind/name key across UID replacement and served API versions. Scoped execution refuses an unspecified coordination namespace. Independent operators with overlapping scopes must be configured to share it. Provider/evidence permissions are unchanged by this coordination choice.

Verification runs at most 32 original observations concurrently under a six-second aggregate deadline. Admission evaluates a terminal check set once and rejects any reused stability timestamp after a runtime fingerprint changes. Unknown/custom health semantics produce coverage gaps until an explicit check is supplied. Initial seed evidence is scoped separately from the legacy targetRef same-namespace dependency exception; out-of-filter owner traversal used by discovery extracts UID/ownership correlation only and never exports parent content.
